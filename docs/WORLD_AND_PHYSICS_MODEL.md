# Модель города, движения и 3D-наблюдения

## Статус и границы

Документ фиксирует целевую модель для всей Астаны. Он не утверждает, что любой автоматически импортированный участок OSM уже совпадает с фактической разметкой до сантиметра. Автоматический импорт даёт полный охват города; качество полос, светофоров, мостов и развязок подтверждается отдельными проверками и версионируемым слоем корректировок.

SUMO остаётся единственным источником истины для движения, дистанций, полос, столкновений и маршрутов. Веб-интерфейс отображает состояние симуляции и не принимает физических решений самостоятельно.

## 1. Представление всей Астаны

### 1.1 Слои данных

| Слой | Содержимое | Источник истины | Назначение |
| --- | --- | --- | --- |
| Транспортный | Рёбра, полосы, связи, ограничения, перекрёстки, светофоры | SUMO `.net.xml` | Расчёт движения и маршрутов |
| Географический | Границы города, вода, здания, парки, названия улиц | снимок OSM | 2D/3D-визуализация |
| Высотный | Мосты, тоннели, эстакады, съезды, уровни пересечений | OSM `bridge`, `tunnel`, `layer`; ручная проверка | Корректный 3D-вид и отсутствие ложных конфликтов |
| Коррекции | Число полос, связи полос, стоп-линии, фазы, уровни, ограничения | репозиторий проекта | Устранение подтверждённых ошибок импорта |
| Сценарный | Погода, трафик, инциденты, депо, вызовы, seed | YAML/JSON сценария | Воспроизводимые эксперименты |

### 1.2 Единый конвейер карты

```text
OSM snapshot Астаны
  -> фильтрация дорожных тегов и ограничений поворота
  -> netconvert / SUMO network
  -> структурная валидация сети
  -> слой ручных корректировок
  -> versioned .net.xml + геоданные для карты
  -> SUMO, backend и 2D/3D-интерфейс используют одну версию карты
```

В репозитории обязательно фиксируются: дата выгрузки, границы выгрузки, версия сети, версия корректировок и хеш итогового `.net.xml`.

### 1.3 Приоритет проверки сети

Полный город импортируется целиком. Ручная проверка идёт очередями:

1. Связность обоих берегов, мосты, тоннели и крупные развязки.
2. Главные магистрали: Мангилик Ел, Туран, Улы Дала, Достык, Сарайшык, Кабанбай батыра, Республика, Богенбай батыра, Абая, Женис, Момышулы, Тауелсиздик, Калдаякова, Сыганак, Алаш.
3. Все светофоры и связи «полоса → полоса» на выбранных экспериментальных коридорах.
4. Остальные дороги: автоматические проверки, затем точечная ручная коррекция по найденным дефектам.

Каждое исправление хранит причину, источник проверки, дату, автора и затронутые OSM/SUMO идентификаторы. Исходные OSM-файлы не редактируются вручную.

## 2. Модель автомобиля

Каждый автомобиль имеет две формы:

- **динамическая форма** — параметры SUMO: длина, ширина, минимальная дистанция, ускорение, комфортное торможение, экстренное торможение и максимальная скорость;
- **визуальная форма** — 2D/3D-модель кузова, ориентированная по углу движения;
- **hitbox** — повёрнутый прямоугольник тех же габаритов, что и динамическая форма. Он доступен для отображения в режиме отладки, но не заменяет расчёт столкновений SUMO.

Минимальные классы: легковой автомобиль, автобус, грузовой автомобиль, скорая помощь, пожарный автомобиль, полицейский автомобиль. Классы различаются размерами и динамическими параметрами.

### 2.1 Состояние на шаге симуляции

```text
vehicle_id, type, route_id, lane_id,
x, y, z, angle,
speed, acceleration, length, width,
driver_state, mission_state, availability
```

Координаты и угол приходят из SUMO. Координата `z` для визуализации выводится из уровня дороги/моста; она не применяется для подмены транспортной логики.

## 3. Динамика скорости и манёвров

### 3.1 Целевая скорость

На каждом шаге оркестратор рассчитывает безопасное ограничение, а SUMO исполняет движение:

```text
v_target = min(
  v_legal,
  v_weather_surface,
  v_curve,
  v_leader,
  v_visibility,
  v_driver,
  v_emergency_manoeuvre
)
```

| Компонент | Причина ограничения |
| --- | --- |
| `v_legal` | лимит дороги, тип машины, локальное ограничение |
| `v_weather_surface` | дождь, снег, гололёд, качество сцепления |
| `v_curve` | малый радиус поворота, съезд, круговое движение |
| `v_leader` | дистанция и относительная скорость впереди идущего транспорта |
| `v_visibility` | туман, ночной сценарий, позднее обнаружение препятствия |
| `v_driver` | реакция, усталость, внимательность и стресс |
| `v_emergency_manoeuvre` | дополнительное ограничение перед выездом на встречную, через линию или в узкий проезд |

Модель не должна выдавать мгновенные изменения скорости. Ускорение и торможение ограничиваются параметрами типа автомобиля. При необходимости торможения учитываются скорость, доступная дистанция, время реакции, коэффициент сцепления и уклон. Коэффициенты погоды являются параметрами сценария с источником/обоснованием, а не скрытыми константами.

### 3.2 Повороты и съезды

Угол автомобиля берётся по касательной к геометрии текущей полосы. На поворотах и съездах целевая скорость ограничивается радиусом траектории и состоянием покрытия. Машина не должна менять направление скачком между рёбрами. Связи полос в `.net.xml` являются единственным допустимым путём через перекрёсток.

### 3.3 Поведение обычных водителей

Обычные водители используют car-following и lane-changing SUMO, дополняемые воспроизводимым профилем:

- внимательность;
- время реакции;
- агрессивность;
- соблюдение ограничения скорости;
- склонность к перестроению;
- вероятность уступить экстренной машине;
- возможность физически освободить полосу.

Профиль создаётся из root seed. Повторный запуск с одинаковыми версиями и seed воспроизводит те же параметры.

## 4. Экстренный транспорт

Экстренная машина обладает обычной физической моделью, но имеет приоритетную стратегию. Разрешённые действия описываются состояниями, а не прямым игнорированием правил:

```text
NORMAL_ROUTE
  -> REQUEST_PRIORITY
  -> RESCUE_LANE
  -> CAUTIOUS_OVERRIDE
  -> STOP_OR_REROUTE
```

| Состояние | Действие | Предохранитель |
| --- | --- | --- |
| `NORMAL_ROUTE` | следует рассчитанному маршруту | обычные ограничения сети |
| `REQUEST_PRIORITY` | запрашивает зелёный коридор | ограничение времени, безопасный возврат фазы |
| `RESCUE_LANE` | гражданские машины пытаются освободить коридор | проверка свободного пространства |
| `CAUTIOUS_OVERRIDE` | исключительный манёвр: объезд, встречная полоса, пересечение разметки | низкая скорость, видимость, TTC, свободная траектория |
| `STOP_OR_REROUTE` | ждёт или перестраивает маршрут | включается при неприемлемом риске |

Ни одно состояние не позволяет проходить сквозь машины, пересекать мостовые уровни или игнорировать возможное столкновение. Манёвры экстренного транспорта должны быть отдельными тестируемыми правилами, чтобы их можно было сравнить с обычным маршрутом.

## 5. Погода, покрытие и видимость

Погода задаётся сценарием и действует на сегменты дороги либо весь город.

| Условие | Сцепление | Видимость | Минимально измеримый эффект |
| --- | --- | --- | --- |
| Сухо | базовое | базовая | исходное время и риск |
| Дождь | пониженное | немного ниже | ниже `v_target`, больше тормозной путь |
| Снег | низкое | ниже | осторожнее повороты, больше интервал |
| Гололёд | очень низкое | базовая/ниже | сильное ограничение торможения и скорости |
| Туман | базовое | низкая | позднее обнаружение, больше реакционная дистанция |

Для MVP влияние реализуется документированными множителями скорости, ускорения, торможения, дистанции и риска. Модель шин, ABS и детальная механика заноса являются расширением и не требуются для доказуемого дипломного эксперимента.

## 6. Светофоры, перекрёстки и уровни дорог

### 6.1 Светофоры

Каждый сигнал имеет штатную программу и управляемые связи. Приоритет экстренной машины возможен только после проверки конфликтующих направлений. После проезда система безопасно возвращается к штатной программе. В лог события записываются причина, начальная фаза, введённая фаза, продолжительность и итог.

### 6.2 Мосты и развязки

Пересекающиеся линии на карте не считаются перекрёстком автоматически. Для каждого сложного участка проверяются:

- `bridge`, `tunnel`, `layer` и геометрия въездов/съездов;
- непрерывность количества полос на подходах;
- отсутствие ложных соединений между разными уровнями;
- корректные повороты и ограничения;
- допустимые маршруты спецтехники.

Если данных о высоте нет, используется визуальный уровень только после ручной пометки. Нельзя выдавать предположение о высоте за проверенный факт.

## 7. Безопасность, ДТП и сообщения

### 7.1 События безопасности

| Событие | Условие | Последствие |
| --- | --- | --- |
| Near miss | TTC ниже зафиксированного порога без контакта | метрика риска, запись в журнал |
| Лёгкое ДТП | контакт на низкой скорости | полиция, возможное частичное перекрытие |
| Тяжёлое ДТП | контакт/сценарная оценка высокой тяжести | полиция, скорая, возможно несколько бригад |
| Пожар/зажатие | подтверждённый признак сценария | МЧС/пожарная, расширенная зона перекрытия |
| Блокировка | закрыта полоса или дорога | событие маршрутизации и пересчёт пути |

Скорость удара сама по себе не ставит медицинский диагноз. Она является входом прозрачного правила тяжести или параметром экспериментального сценария.

### 7.2 Коммуникационный журнал

Чат диспетчера — это отображение event log, а не свободная имитация переписки. Каждое сообщение имеет отправителя, получателя, время создания, время доставки, основание и идентификатор события.

```text
Incident Agent -> Dispatcher: ДТП подтверждено
Dispatcher -> Police: назначение экипажа
Dispatcher -> Ambulance: назначение/отмена/переназначение
Routing Agent -> Vehicle: новый маршрут
Traffic Light Agent -> Vehicle: коридор активирован
```

Задержка сообщения параметризуется и обязательно попадает в результаты эксперимента.

## 8. 2D/3D-интерфейс и производительность

Полная Астана существует в карте и в симуляции, но не все объекты рисуются с максимальной детализацией одновременно.

| Масштаб/режим | 2D-карта | 3D-сцена |
| --- | --- | --- |
| Город | магистрали, районы, агрегированная плотность, активные инциденты | не требуется |
| Район | дороги, светофоры, агрегированные автомобили | здания и ключевые дороги в видимой области |
| Участок | полосы, маршруты, отдельные машины | модели автомобилей, мосты, hitbox, траектории |
| Отладка | TTC, перекрытия, связи полос | hitbox, безопасная дистанция, уровни дорог |

2D-карта получает полную географию, разделённую на тайлы. 3D-сцена отображает только область камеры и нужные ближайшие объекты. Далёкий транспорт агрегируется, но никогда не исчезает из расчёта SUMO.

Целевой интерфейс:

```text
центр / слева: 3D-наблюдение за выбранным экипажем или ДТП
справа сверху: 2D-карта всей Астаны
справа снизу: журнал диспетчера и состояние операции
```

Нажатие на объект на 2D-карте перемещает 3D-камеру; запись журнала ведёт к связанному инциденту. API кадров передаёт только изменившиеся сущности и использует пакеты кадров, а не HTTP-запрос на каждый автомобиль.

## 9. Порядок реализации

1. Зафиксировать версию полной сети и автоматические проверки связности.
2. Ввести реестр ручных корректировок и перечень проверенных мостов/перекрёстков.
3. Стандартизировать классы машин, габариты и параметры SUMO.
4. Реализовать погодные множители, водительские профили и безопасную целевую скорость.
5. Закрыть тестами приоритет светофора, уступание, ДТП, блокировку и перерасчёт маршрута.
6. Отдать из Python кадры состояния и event log.
7. Построить 2D-карту всей Астаны с тайлами и выбором объекта.
8. Добавить 3D-наблюдение за выбранным автомобилем, модели машин и режим hitbox.
9. Провести детерминированные эксперименты: seed, 100+ машин, разные погоды и инциденты.

## 10. Критерии готовности

- Весь город загружается из зафиксированной версии карты, а сеть проходит структурную проверку.
- Переходы между двумя берегами и проверенные мосты проезжаемы, без ложных соединений уровней.
- Сценарий с одинаковым seed воспроизводит одинаковые решения, события и показатели baseline-режима.
- Погода измеримо меняет хотя бы скорость, время прибытия или метрику риска.
- Экстренная машина получает приоритет только с журналируемым правилом безопасности.
- ДТП закрывает указанную полосу/дорогу, информация доходит до диспетчера, назначаются нужные ресурсы и маршрут пересчитывается.
- 2D-карта показывает всю Астану, а 3D-камера корректно следует за выбранной машиной по её фактическим координатам и углу.
- Hitbox в интерфейсе совпадает с длиной, шириной и углом транспортного средства в кадре SUMO.
