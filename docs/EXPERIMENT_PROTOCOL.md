# Протокол числовой проверки

## Назначение

Протокол нужен для сравнения маршрутизации и поведения системы на одинаковых
условиях. GUI SUMO используется только для визуальной проверки; основными
доказательствами являются журналы, метрики и повторяемость запусков.

## Единица эксперимента

Один запуск определяется кортежем:

`network_hash + scenario_version + sumo_version + tls_mode + weather + strategy + seed`

Каждый запуск получает `run_id`. Случайность обычных водителей, спроса,
уступания и инцидентов получает отдельный генератор, производный от корневого
seed.

## Контрольные группы

- `TLS normal` — штатные светофоры;
- `TLS off` — контроль влияния светофоров;
- `nearest_free + Dijkstra` — базовый алгоритмический baseline;
- `traffic_aware` — baseline с текущим временем проезда;
- позже `PPO` — обучаемый baseline с теми же сценариями.

Меняется только один фактор за один сравнительный блок. Сеть, demand,
количество машин и точки вызовов должны совпадать.

## Нагрузка

Первый контролируемый сценарий: 100 обычных автомобилей и 2 экстренные
машины. При необходимости число экстренных машин меняется отдельным фактором,
но не скрывается внутри числа 100.

## Метрики

- среднее и P95 времени прибытия;
- доля успешных вызовов;
- число переназначений;
- ДТП и near-miss;
- минимальный и P5 TTC;
- средний и максимальный стресс водителя;
- задержка обычного транспорта;
- длина маршрута;
- средняя скорость и время ожидания на светофорах;
- число попыток уступания и процент успешных уступаний.

## Повторяемость

Для smoke-серии используются seeds `42`, `43`, `44`. Для итоговой серии
используется минимум 10 заранее перечисленных seeds. Повтор seed `42` должен
дать одинаковые назначения, события и итоговые значения в допустимом допуске.

## Артефакты запуска

```text
experiments/results/<run_id>/
  scenario.json
  run_metadata.json
  event_log.jsonl
  calls.csv
  vehicles.csv
  metrics.json
  summary.txt
```

## Критерии остановки

Эксперимент не считается успешным, если:

- есть незапротоколированное исчезновение автомобиля;
- маршрут не завершён и причина не записана;
- seed или версия сети не записаны;
- в режиме `TLS off` остались фазовые ожидания из-за ошибки конфигурации;
- lane drop появился после сборки без записи в override;
- один и тот же seed даёт разные результаты за пределами допуска.
