# Routing baselines

## Назначение

Проект сравнивает три алгоритмические стратегии на одинаковой сети, OD-парах
и seed. Они являются контрольной группой для будущей PPO-политики.

- `dijkstra` — статический кратчайший путь по длине, реализованный `sumolib`;
- `astar` — статический кратчайший путь с геометрической эвристикой;
- `traffic_aware` — начальный быстрый путь с периодическим пересчётом маршрута
  экстренной машины по текущему времени движения SUMO.

## Корректность A*

SUMO-сеть может загружаться без внутренних полос перекрёстков. В таком графе
необработанное евклидово расстояние иногда переоценивает остаточную стоимость,
поскольку переход через junction не имеет отдельного веса. Поэтому эвристика
масштабируется минимальным отношением стоимости следующего ребра к
геометрическому смещению между соседними состояниями. Это обеспечивает
согласованность эвристики и сохраняет оптимальность A*.

Проверка на полной сети Астаны для 102 OD-пар при seed 42 дала максимальную
разницу стоимости A* и Dijkstra `1,46e-11`, то есть только погрешность
вычислений с плавающей точкой. Неоптимальных маршрутов не обнаружено.

## Пилотный прогон

Контрольные запуски `dijkstra` и `astar` использовали одну сеть, seed 42,
100 обычных и 2 экстренные машины. Оба режима завершили 102/102 маршрута и
2/2 вызова без ДТП. Среднее время экстренной машины составило 1571 с, P95 —
1612,4 с, средняя длина экстренного маршрута — 21708,76 м. Построение 102
начальных маршрутов заняло около 8,52 с у каждого режима.

Один seed не доказывает вычислительного преимущества алгоритма. Финальный
эксперимент должен повторить измерение на нескольких seeds и отдельно
сравнить время планирования, время прибытия, длину маршрута и влияние на
обычный транспорт.
