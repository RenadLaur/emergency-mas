# ДТП на умном перекрёстке: полный цикл реакции

Контролируемый сценарий моделирует один инцидент с одним пострадавшим, дымом
и перекрытой полосой. Это заранее заданные входные признаки симуляции, а не
медицинская оценка по скорости столкновения.

Последовательность:

1. На 15-й секунде закрывается полоса `west_in_0`.
2. Через одну секунду датчик формирует сообщение; ещё через две секунды оно
   доходит до диспетчера.
3. `ResponsePlanner` направляет полицию, одну скорую и пожарно-спасательный
   экипаж; каждое назначение — отдельный response call.
4. Уже движущаяся скорая получает через секунду команду занять временный
   emergency bypass corridor: крайняя полоса свободна только в рамках этого
   контролируемого эксперимента.
5. Светофор безопасно даёт ей приоритет, а журнал фиксирует прибытие всех
   экипажей.

TTC и near-miss записываются отдельно: приоритет не имеет права отменять
безопасность. В этом сценарии они являются измеряемым результатом, а не
искусственно обнуляются.

Трёхполосная сеть этого сценария изолирована от остальных демонстраций:
перекрывается полоса 0, обычный поток удерживается на полосе 1, а временный
коридор использует полосу 2. На городской карте свободный коридор должен
определяться из фактической геометрии и занятости полос.

Запуск:

```bash
python simulation/sumo/intersection_incident_response/run.py
python simulation/sumo/intersection_incident_response/run.py --gui
```

Выходы: `output/run_summary.json` и `output/event_log.jsonl`.

A/B-сравнение с теми же seed и транспортным спросом:

```bash
python simulation/sumo/intersection_incident_response/compare.py
```

Оно создаёт `output/comparison.json`, а отдельные сводки и журналы сохраняются
с суффиксами `no_corridor` и `corridor`.

Критерий текущего эксперимента: коридор должен сокращать время прибытия и не
увеличивать near-miss. Нулевую разницу near-miss нельзя описывать как снижение
риска — это только отсутствие ухудшения в данном запуске.
